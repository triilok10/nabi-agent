# Nabi

Nabi is a local-first Flutter app foundation for Android and Windows. This
stage sets up the Flutter app, local SQLite memory, CI, an Android build
container, and local SMTP/Ollama test services.

## Privacy behavior in this stage

- The call-assistant switch is a session-only preference. This build does not
  answer calls, capture call audio, or activate an accessibility service.
- The daily background task only prepares a private JSON archive on-device.
  The app displays the archive before a user can mark its records archived.
- Email is never sent by background work. Sending requires runtime SMTP
  settings and a separate recipient-specific confirmation after review;
  credentials are not persisted.
- Android cloud backup is disabled. Location and microphone permissions do not
  trigger access by themselves; user-initiated features are not implemented in
  this stage.

## Local development

Run the local SMTP test server and Ollama with:

```powershell
docker compose -f docker\docker-compose.yml up -d
```

Mailpit's SMTP endpoint is `localhost:1025` and its inbox UI is
`http://localhost:8025`. Ollama listens on `localhost:11434`.

The Android platform scaffold is generated by CI and Docker from the installed
Flutter SDK, preserving `android/app/src/main/AndroidManifest.xml`. To generate
it in a local Flutter/Linux environment, run
`bash scripts/ensure-android-scaffold.sh`, then `flutter pub get`,
`flutter analyze`, `flutter test`, and `flutter build apk --release`.

The model-assets directory is intentionally empty; no model weights or
credentials are included in this repository.
