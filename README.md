# Nabi

Nabi is a local-first Flutter app foundation for Android and Windows. This
stage sets up the Flutter app, local SQLite memory, CI, an Android build
container, and local SMTP/Ollama test services.

## Local-first behavior

- The call-assistant switch is a local SQLite preference only. This build does not
  answer calls, capture call audio, or activate an accessibility service.
- Commands and responses are processed on-device and stored in SQLite's
  `memory_logs` table. Before inference, relevant recent local turns are added
  to the prompt as untrusted context. Nabi uses a local GGUF model through
  `llamadart`; it does not fetch models or send prompts to a remote service.
- The model emits a structured JSON intent. Dart validates the schema, and
  Android executes only the supported actions: launching an installed app by
  its exact displayed name, opening the camera UI, toggling the flashlight,
  and opening selected system settings. This does not read notifications,
  capture a photo automatically, or grant accessibility control.
- Voice is push-to-talk while Nabi is open. The app requests microphone
  permission when the user starts recording, records a temporary mono WAV,
  transcribes locally through `whisper_ggml`/whisper.cpp, deletes the audio
  after transcription, then logs the transcript as a command. There is no
  always-listening background microphone service.
- Responses can be spoken with the device's installed TTS engine. TTS is
  invoked for user-submitted commands and does not upload text.
- Nabi stores data in app-private storage. On Android 13 and later, app-private
  files do not require broad storage permission; older Android versions request
  legacy storage access only after the user asks for it.
- The daily background task only prepares a private JSON archive on-device.
  The app displays the archive before a user can mark its records archived.
- Email is never sent by background work. Sending requires runtime SMTP
  settings and a separate recipient-specific confirmation after review;
  credentials are not persisted. An approved archive can include local command
  and response logs.
- Android cloud backup is disabled. Microphone and storage permissions do not
  trigger access unless the user initiates a request.

## Local model files

The app never downloads model files automatically. Copy a compatible GGUF chat
model to the app's private application-support directory as
`models/nabi-model.gguf`. Copy the multilingual Whisper `base` model to
`ggml-base.bin` in the support directory reported by
`WhisperController.getPath(WhisperModel.base)`. The UI shows the GGUF load
status; voice transcription reports a missing Whisper file when the user stops
recording. Provide the model files securely as part of your local deployment;
weights are not included in this repository.

Whisper's Android plugin requires Android API 24 or later. The Android scaffold
script sets that minimum version when it generates the Gradle files. Offline
voice recognition also requires the Whisper model to be present before use.
This project requires Dart 3.10.7 or later and Flutter 3.44 or later for the
selected local inference and recording packages.

## Local development

Run the local SMTP test server and Ollama with:

```powershell
docker compose -f docker\docker-compose.yml up -d
```

Mailpit's SMTP endpoint is `localhost:1025` and its inbox UI is
`http://localhost:8025`. Ollama listens on `localhost:11434`.

The Android platform scaffold is generated by CI and Docker from the installed
Flutter SDK, preserving the manifest and Nabi's system-action platform channel.
To generate it in a local Flutter/Linux environment, run
`bash scripts/ensure-android-scaffold.sh`, then `flutter pub get`,
`flutter analyze`, `flutter test`, and `flutter build apk --release`.

The model-assets directory is intentionally empty; no model weights or
credentials are included in this repository. Local model files belong in the
app's private support directory, not in source control.
